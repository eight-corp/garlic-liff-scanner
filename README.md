# にんにく冷蔵庫管理

このリポジトリの正式版は、GitHub Pages上のUIとSupabase DBを使う方式です。

## 注文管理

`orders/` は共通ログインで利用するカテゴリ別の注文・承認・進捗・分納管理です。
業務管理メニューの旧「黒にんにく出荷管理」と同じアプリ権限IDを使います。

- 初回は共通認証スキーマの導入後、`orders/schema.sql` をSupabaseに適用します。再適用可能です。
- ユーザー情報の「注文管理」で利用権限を設定します。商品・取引先・配送業者のマスタ編集は同アプリの管理者のみです。
- 注文の確定・差戻し・取消、出荷の取消には「注文承認」のチェックと、注文管理の作業者以上の権限が両方必要です。管理者にも自動付与しません。
- 商品には乾燥にんにく・黒にんにく・にんにく加工品のカテゴリを設定します。注文自体にはカテゴリを保存せず、1件の注文に複数カテゴリの商品を登録できます。一覧は注文ごとに1行で、含まれる商品のカテゴリを表示します。カテゴリを絞り込むと、そのカテゴリの商品を含む注文が残ります。マスタの初期データは空です。
- 「注文入力」は取引先名・出荷希望日・納品先名・備考を入力し、カテゴリ・品名・数量の明細を複数登録します。注文日は新規保存時の日本時間の日付、登録担当者は入力者です。一覧・検索は「注文検索」で行います。タブ移動と自動同期では入力を保持し、クリアまたは登録成功時に新規入力へ戻します。閲覧者の初期画面は注文検索です。
- 注文入力と下書き・差戻しの編集では、取引先・納品先・商品欄の虫眼鏡から候補を検索し、見つからなければその場でマスタに新規追加して選択できます。作業者以上が新規追加でき、既存マスタの編集は引き続き管理者のみです。商品はその明細のカテゴリ、納品先は現在の取引先で絞り込みます。マスタの登録と注文の保存は別操作です。
- 注文入力と下書き・差戻しの編集では、各明細の入数（商品マスタ）と合計数（数量×入数）、全明細の合計数を表示します。入数や数量が未確定の明細がある間、全明細の合計数は未確定と表示します。保存する明細数量や出荷残数は換算しません。
- 商品マスタはカテゴリ・商品名・規格・入数・大箱入数・バンド・JANコード・備考の順で表示します。JANコードは任意で、未入力の商品を複数登録できます。入力されたJANコードが重複する場合は警告を表示しますが、保存できます。バンドは1個口にまとめられる箱数（正の整数または未設定）を保存し、荷物数の自動計算は行いません。入数は正の整数または未設定で、旧来の数量単位とは別に保存し、既存注文の数量換算は行いません。
- 取引先マスタは店舗名・郵便番号・取扱商品（複数）・基本の配送業者を登録できます。取扱商品はマスタ情報として保存し、注文入力の商品選択を制限しません。配送業者は出荷登録の初期値に使い、個別に変更できます。
- 取引先の編集で納品先名・郵便番号・住所・電話番号を複数登録できます。注文入力では納品先名だけを選択・追加します。その場で追加する取引先も名称だけで登録でき、内部コードは自動で付与します。1件目の納品先は取引先自身で、名称・店舗名・郵便番号・住所・電話番号から自動設定し、注文入力でも初期選択します。既存の住所・電話番号は保持し、注文画面では表示しません。旧注文は「保存済み」の納品先のまま編集できます。
- 進捗一覧で承認待ちの注文を開いて確定します。注文承認の権限がある担当者は配送業者を選択でき、未登録の業者は名称を入力して確定と同時にマスタへ追加できます。設定した業者は出荷登録の初期値になります。
- FAXの写真やメールのスクリーンショットなどを注文入力時に任意で5枚まで添付できます。ブラウザでJPEGに変換して注文と同時に保存し、注文詳細から権限のある利用者のみが開けます。添付の画像本体は一覧や自動同期に含めません。PDFやメールの原本は対象外です。
- 先方注文番号は入力・詳細画面から除外しています。既存の番号はデータベース内に保持し、注文を編集しても消去しません。
- 出荷準備完了の明細を分納でき、未出荷残数を超える出荷は禁止します。取消履歴は残します。在庫管理とは連動しません。
- 「進捗一覧」は下書き・承認待ち・出荷済み・取消を含むすべての状態を初期表示します。列見出しのフィルターで候補を選んだり文字を入力したりでき、複数列の条件は注文全体に適用します。進捗更新は確定済みの注文のみ可能です。
- 変更は4秒ごとに共通認証付きRPCで検出します。未保存の入力は保持し、競合した保存は拒否します。
- ローカル検証は `orders/` で `npm ci`、`npm test`、`npm run test:browser`、`node tests/account.browser.mjs`。ブラウザーテストにはChromeが必要です。外部通信は遮断し、PGlite内でのみ業務データを変更します。
