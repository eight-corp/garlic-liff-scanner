# にんにく冷蔵庫管理

このリポジトリの正式版は、GitHub Pages上のUIとSupabase DBを使う方式です。

## 注文管理

`orders/` は共通ログインで利用するカテゴリ別の注文・承認・進捗・分納管理です。
業務管理メニューの旧「黒にんにく出荷管理」と同じアプリ権限IDを使います。

- 初回は共通認証スキーマの導入後、`orders/schema.sql` をSupabaseに適用します。再適用可能です。
- ユーザー情報の「注文管理」で利用権限を設定します。商品・取引先・配送業者のマスタ編集は同アプリの管理者のみです。
- 注文の確定・差戻し・取消、出荷の取消には「注文承認」のチェックと、注文管理の作業者以上の権限が両方必要です。管理者にも自動付与しません。
- 商品には乾燥にんにく・黒にんにく・にんにく加工品のカテゴリを設定します。注文はカテゴリごとに登録します。マスタの初期データは空です。
- 「注文入力」は新規入力フォームを常設し、一覧・検索は「注文検索」で行います。タブ移動と自動同期では入力を保持し、クリアまたは登録成功時に新規入力へ戻します。閲覧者の初期画面は注文検索です。
- 商品マスタはカテゴリ・商品名・規格・入数・大箱入数・バンド・JANコード・備考の順で表示します。JANコードは任意で、未入力の商品を複数登録できます。入力されたJANコードは重複を禁止します。バンドは1個口にまとめられる箱数（正の整数または未設定）を保存し、荷物数の自動計算は行いません。注文入力・絞り込み・一覧・詳細も「カテゴリ」に統一し、既存の `department` 項目で保存します。入数は正の整数または未設定で、旧来の数量単位とは別に保存し、既存注文の数量換算は行いません。
- 取引先マスタは店舗名・郵便番号・取扱商品（複数）・基本の配送業者を登録できます。取扱商品はマスタ情報として保存し、注文入力の商品選択を制限しません。配送業者は出荷登録の初期値に使い、個別に変更できます。
- 取引先の編集で納品先名・郵便番号・住所・電話番号を複数登録できます。注文入力は納品先を選ぶ方式で、住所・電話番号は表示専用です。有効な納品先が1件だけなら自動選択します。削除した納品先は無効化して履歴を残し、既存注文の保存時点の住所・電話番号は変更しません。旧注文は「保存済み」の納品先のまま編集できます。
- 先方注文番号は入力・詳細画面から除外しています。既存の番号はデータベース内に保持し、注文を編集しても消去しません。
- 出荷準備完了の明細を分納でき、未出荷残数を超える出荷は禁止します。取消履歴は残します。在庫管理とは連動しません。
- 変更は4秒ごとに共通認証付きRPCで検出します。未保存の入力は保持し、競合した保存は拒否します。
- ローカル検証は `orders/` で `npm ci`、`npm test`、`npm run test:browser`、`node tests/account.browser.mjs`。ブラウザーテストにはChromeが必要です。外部通信は遮断し、PGlite内でのみ業務データを変更します。
